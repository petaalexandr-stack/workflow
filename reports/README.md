# Отчёты испытаний — отдельно от исполняемого Workflow

Здесь собираем **обезличенные** результаты работы Codex App и Python Workflow. Это не папка `.workflow/` с базой контроллера и не папка с исходниками `workflow/`.

### Как добавить новый MD после запуска

1. Сохрани сырой файл из Codex App локально в `reports/incoming/` (не попадёт в Git) или приложи его в текущем обсуждении.
2. Скопируй `reports/_TEMPLATE.md` → `reports/runs/YYYY-MM-DD-S01-I01A-<short-name>.md`.
3. Заполни статус, Git branch/commit, версию Codex App/CLI, входную команду, ожидаемое/фактическое, thread/turn, stderr, тесты, diff, подтверждение открытия чата.
4. Удали из публикуемой версии приватные данные, токены, полные пути к пользовательским каталогам. Сырой SQL/JSONL/SQLite не загружать в Git.
5. Пришли мне ссылку на опубликованный MD (или исходный MD в чат). Сопоставим с планом и подготовим следующую точечную итерацию.

Разделы отчёта: `Observed` — подтверждено журналом, `Inferred` — правдоподобное объяснение, `Open` — нуждается в следующем тесте. Не склеивай несколько прогонов в одно непроверяемое описание. Пример — `samples/2026-10-26-original-first-run-summary.md`.

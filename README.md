# Workflow Lab — разработка Workflow для Codex App

**Назначение репозитория:** безопасно улучшать и проверять движок Workflow v0.7, работающий с **Codex App / авторизованным Codex CLI**, **без прямых вызовов моделей через собственный OpenAI API key**.

**Состояние:** подготовлена исходная копия v0.7 и документация для итерационного тестирования. Исправлены только узкие Windows-дефекты обнаруженного в CI запуска (разбор пути CLI и кодировка эмулятора JSONL); остальные проблемы Codex Bridge **ещё не исправлены**. Настоящая проверка на машине пользователя **не пройдена**. Текущий репозиторий — лаборатория разработки движка, не готовый продукт для бизнеса.

## Начать работу

1. Прочитать [HOW_WE_WORK.md](HOW_WE_WORK.md) и [docs/ROADMAP.md](docs/ROADMAP.md).
2. В **Codex App открыть корень репозитория**, а не случайный родительский `C:\agentic_2026` и не папку с историческим оригиналом.
3. Запустить офлайн-тесты исходного движка: `cd workflow` → `python -m unittest discover -s tests -v` (Python 3.11+).
4. Проверить Git-корень: `git rev-parse --show-toplevel`; сравнить его с открытой папкой Codex App.
5. Использовать текущий план в [docs/ITERATION-01.md](docs/ITERATION-01.md); **не запускать `next` на реальном Codex до согласования конкретного теста**.
6. После каждого испытания заполнить [reports/_TEMPLATE.md](reports/_TEMPLATE.md), сохранить очищенный отчёт в `reports/samples/` или `reports/runs/`, прислать ссылку/MD на разбор.

> Для запуска CLI из корня репозитория нужен пакет: `python -m pip install -e ./workflow`. Корень проекта в CLI (`--project .`) и путь к идеям **пока расходятся**: текущий `--idea` ищет `<project>/ideas`, а исходные примеры лежат в `workflow/ideas`. Это задача будущей итерации; не копировать идеи наугад и не использовать `--idea` до исправления маршрутизации путей.

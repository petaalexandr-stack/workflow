# Codex App ↔ Workflow v0.7

## Компоненты

- `.agents/skills/workflow-ideas/SKILL.md` — вход из обычного Codex-чата. Skill НЕ содержит ключей и не подтверждает этапы самостоятельно.
- `workflow_engine/codex/client.py` — Codex app-server JSONL protocol; явные `thread/start`, `thread/name/set`, `thread/resume`, `turn/start`; ожидание `turn/completed`.
- `workflow_engine/codex/provider.py` — адаптер выбранного агента. Один модуль → один или несколько **последовательных** независимых чатов. Нет Codex subagents.
- `workflow_engine/codex/threads.py` — сохранение `run_id / module_id / role → thread_id` и флага `pending`.
- `workflow_engine/controller.py` — единственный источник истины для текущего этапа и разрешений.

## Установка

```bash
python -m pip install -e .
workflow --project . codex-install-skill --scope project
workflow --project . codex-doctor
```

Убедись, что `codex` установлен, авторизован и доступен через PATH. Затем открой проект в Codex App и попробуй:

> Передай оркестратору идею из `ideas/my-idea.md`. Сначала уточни понимание задачи и согласуй со мной маршрут.

Можно вызвать `$workflow-ideas` явно. Видимость внешне созданных потоков в открытом Codex App может зависеть от версии клиента — отдельно проверь на своей установке.

## Чаты

- `WF-<runid> · 00 · Orchestrator` — понимает запрос, предлагает упорядоченные модули, подготавливает отчёты.
- `WF-<runid> · <moduleid> · <agent>` — только роль и локальный контекст.
- При отклонении задания повторный ход идёт **в тот же чат** соответствующего исполнителя.
- Новый модуль получает ссылки на утверждённые `handoff.md`, `system-design.md` и только выбранные предыдущие результаты.

## Безопасность и ограничения

Перед `turn/start` Bridge задаёт Codex sandbox-policy `readOnly` или `workspaceWrite` (только для ролей writer при отдельном флаге). При `requestApproval` Bridge не предоставляет дополнительные разрешения. Важный нюанс: `--allow-shell` для Codex — текстовое ограничение в инструкции, не независимое OS-ограничение; при необходимости используй внешнюю изоляцию.

По умолчанию Bridge отслеживает изменения через Git diff и HEAD. На сомнительных ситуациях помечает модуль заблокированным. Если Codex оборвал ход, он остаётся `pending`: **не запускай его автоматически повторно**.

## Что тестируется офлайн

`tests/fake_codex_app_server.py` проверяет создание, именование, продолжение чатов, структурированные результаты, отказ в повышении прав, сохранение thread_id и блокировку неопределённых ходов. Живую интеграцию с твоим Codex App и реальное отображение чатов эти тесты не гарантируют.

# Миграция v0.6 → v0.7

## Что изменено

**Удалено:** `engine.py` (DAG scheduler), `stage_loop.py`, блочное делегирование/Block Coordinator и legacy-команды `approve-step`, `steps`, `set-mode`.

**Добавлено:** `controller.py`, каталог независимых контрактов `workflow_engine/modules/`, единый вход `next`/`review`/`approve` для одного текущего модуля.

**Сохранено:** `agents/*.md` (13 ролей), папка `ideas/`, Codex app-server Bridge, именованные чаты, SQLite, контрольные точки, инструменты, System Design light/full, финальный Documentation.

## Прежние активные запуски

Прежние состояния в SQLite **не переводятся автоматически**: у v0.6 DAG и у v0.7 последовательного списка разные правила согласования и пересмотра. Автомиграция могла бы ошибочно признать согласованным то, что пользователь не подтверждал.

- Для завершения старого запуска используй исходный v0.6.
- Для нового задания используй v0.7, начиная с обсуждения и двух согласований заново.
- Не удаляй старую `.workflow/`: она содержит аудит и артефакты. Рекомендуется сохранить её резервную копию.

## Поддерживаемость

Контракт каждого модуля находится в отдельном Python-файле `workflow_engine/modules/*.py`. Промпты остаются раздельными Markdown-файлами `agents/*.md`. Общая логика согласования находится **только** в `controller.py`, без её копирования в каждый модуль. Для более сложной параллельности можно сделать отдельный явно выбранный режим позднее, но первая реализация строго последовательная.

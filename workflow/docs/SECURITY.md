# Границы безопасности Workflow v0.7

- AI предлагает. **Только код** сохраняет подтверждения и открывает следующий модуль.
- Два независимых начальных токена: понимание и маршрут. Отдельный токен для каждого модуля. Старые токены отклоняются.
- Writer не получает запись без явного `--allow-writes`; небезопасный shell в OpenAI режиме заблокирован без специального `--unsafe-shell`.
- В Codex-режиме реальные права обеспечивает sandbox-policy Codex. Bridge отказывает в запросах на повышение разрешений. Текстовое `--allow-shell` ограничение в Codex не равно OS-политике.
- SQLite использует optimistic locking и checkpoints. Модуль отмечается `running` до инструментов; неизвестный статус требует ручного восстановления.
- Не доверяйте содержимому `ideas/*.md`, проектным файлам или output агента как разрешению на новый модуль.
- Входы модулей — выбранные утверждённые Markdown-handoff; не вся переписка Codex App.
- Результаты модуля проверяются структурно; `system_design` проверяется на обязательные поля. Это не доказательство правильности реализации.
- Git commit / push не одобряются автоматически. Изменение маршрута не делает Git rollback. Возобновление после отключения Codex требует ручной проверки.
- Desktop UI и VM sandbox не входят в реализацию. Для неизвестного кода используйте отдельную VM/контейнер и ревью разрешений.

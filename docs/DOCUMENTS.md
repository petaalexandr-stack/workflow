# Политика документов и отчётов

Задача — иметь достаточно доказательств для решения, **не** заставляя Codex перечитывать десятки дублирующихся MD.

| Документ | Единственный вопрос, на который отвечает | Когда менять |
|---|---|---|
| `README.md` | что это за репозиторий и с чего начать? | при изменении структуры |
| `AGENTS.md` | что Codex обязан соблюдать? | редко; короткий набор правил |
| `HOW_WE_WORK.md` | как проходит итерация и согласование? | при изменении процесса |
| `docs/ROADMAP.md` | какой следующий проверяемый этап? | после решения/приёмки |
| `docs/ITERATION-01.md` | что именно делаем прямо сейчас? | во время первой серии |
| `docs/FILE-AUDIT.md` | что полезно, что подозрительно, что удалено? | при чистке файлов |
| `docs/DECISIONS.md` | какие архитектурные решения утверждены? | только по явному решению |
| `reports/runs/YYYY-MM-DD-...md` | что **фактически** произошло в конкретном запуске? | после каждого live теста |
| `workflow/docs/*` | как устроен **текущий движок**? | синхронно с изменением кода |

### Обработка входящего отчёта

1. Поместить полученный Markdown в локальную папку `reports/incoming/` (игнорируется Git). Для живого отчёта заполнить [шаблон](../reports/_TEMPLATE.md).
2. Скрыть имена пользователей/домашние каталоги, токены/ключи, cookies, персональные данные клиентов, содержимое чужих чатов и служебные дампы. Не коммитить весь JSONL/SQLite/.codex.
3. Сформировать **краткий обезличенный** `reports/runs/YYYY-MM-DD-stage-iteration.md` с ожидаемым, фактическим, командами, воспроизведением, выводами, решением.
4. Связать отчёт с веткой, коммитом и соответствующей итерацией в roadmap; не переписывать исторические факты после исправления — создать новую запись.
5. В отдельном разделе фиксировать `observed`, `inferred`, `not tested`, чтобы гипотезы не становились «успехами».

**Важно:** папка `reports/` — это лаборатория тестирования самого Workflow, **не** runtime-хранилище `.workflow/` и **не** документация приложения, которое разработает агент. Оригинальные секретные логи не публиковать в открытый GitHub даже при удобстве отладки.

## Откуда сложность (подтверждённое vs гипотезы)

**Подтверждено по коду и MD:** устаревший `readOnly.access`; отсутствие автоматической UI-навигации в CLI; `--idea` привязан к project root; риск неполного bootstrap роли при чате без первого хода; Git snapshot тихо пустой при ошибке Git; в `_context` нет промежуточных итогов коллег из текущего модуля; отдельный режим `openai` присутствует, хотя в историческом запуске использовался `codex`.

**Гипотезы до живого сравнения:** нативный Codex App может заменить часть Bridge; часть модулей может быть избыточна для коротких задач; число человеческих gates можно оптимизировать; `readOnly` и permissionProfile могут требовать разных настроек в разных версиях. Гипотезы не становятся решением без протокола испытаний.

## Порядок чистки

1. Заморозить baseline и проверить импорты/тесты.
2. Запустить 01A: нативный Codex и Bridge на одинаковом задании.
3. Записать ADR в `docs/DECISIONS.md`: что оставляем и почему.
4. Отдельный PR на один блок удаления/замены; приложить regressions/миграционные действия.
5. После принятия обновить README, legacy docs, установку и report template.

Сейчас мы **сознательно сохранили все 61 файла источника**, поскольку удаление без регрессионных проверок противоречит поэтапной схеме.

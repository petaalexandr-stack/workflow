# Журнал архитектурных решений (ADR)

## ADR-000 — baseline без удаления (proposed, 2026-10-26)

- Контекст: исходный ZIP v0.7 содержит исполняемый CLI, контроллер, API-альтернативу, Codex Bridge, 9 модулей и 2 внутренних шага. В отчёте живого запуска отмечены ошибки протокола/UI, но полный E2E не проводился.
- Решение для подготовки: импортировать структуру целиком в `workflow/`; не удалять потенциально используемый код до контролируемого сравнения A/B.
- Безопасность: хранить только очищенные отчёты в публичном репозитории.
- Не принято: выбор нативного Codex против Bridge, удаление OpenAIProvider, изменение схемы gates, изменение sandbox policy.

## ADR-000A — Windows command parsing (implemented for CI, 2026-10-26)

- Обнаружение: базовые 29 тестов на GitHub Actions прошли в Linux, но на Windows четыре интеграционных проверки не могли запустить fake app-server: `WinError 2`.
- Причина: `shlex.split(...)` в POSIX-режиме удаляет обратные слеши из Windows-путей `WORKFLOW_CODEX_COMMAND`.
- Минимальное изменение: платформозависимый разбор строки команды, сохранение обратных слешей и корректная обработка кавычек; 2 unit-теста без реального Codex.
- Область доказательств: локально 31 тест пройден на Linux. Первый повторный Windows CI выявил вторую проблему: эмулятор использовал системную кодировку для JSONL и своего состояния, повреждая русскоязычный текст. Явно заданы UTF-8 для stdin/stdout и state. Итог GitHub Windows CI и работа реального Codex App требуют отдельного подтверждения. **Это не исправление `readOnly.access` или UI-навигации**.

## ADR-001 — Native Codex App vs Bridge (pending)

- Критерии: UX, доступ к файлам, видимость и открытие чатов, утверждения, сохранение состояния, восстановление после сбоев, время/сложность поддержки.
- Доказательства: два отчёта 01A на одинаковой короткой задаче.
- Итог: **ожидает испытаний и явного решения пользователя**.
